# コーディング上の共通事項

- 本人の書いたコードについて「修正点を教えて」など確認・指摘を求められた場合は、問題点を具体的に指摘するだけでコードを変更しない。「直して」「修正して」と依頼された場合は、問題点を具体的に指摘したうえで、依頼された範囲を修正する。追加の修正依頼を待つ必要はない。
- 関数定義・呼び出しの引数は横並びで書く。
- コード内の不要な改行・空行を増やさず、簡潔に書く。
- 関数の説明は関数定義の前に書く。関数本体の先頭に三重引用符で囲んだ説明（docstring）を置かない。
- 処理を上から順に追えるようにし、短い処理を細かい補助関数へ分割しすぎない。
- 変数名はJ、sigma、eigvecなど、数式との対応や計算上の意味が直接分かるものを使う。
- コメントは日本語で、行ごとの説明ではなく、処理のまとまりごとの目的・段階を書く。
- 関数の説明には戻り値の配列形状（shape）と、各列が何を表すかを書く。
- 長い一行に計算を詰め込まず、確認したい中間結果には名前を付ける。引数は横並びにするが、計算過程は省略しすぎない。
- 余計なバグ対策・入力検証・例外処理・フォールバックは基本的に追加しない。追加したい場合は、理由を説明して本人に相談してから実装する。
- 調整パラメータはmainで指定し、moduleへ引数で渡す。module内に具体的な既定値を置かない。数式上の定数や添字は区別する。
- 構造の次元はmainのDIMENSIONから引数dimensionとして渡し、2(2D)／3(3D)で統一する。mechanicsの評価では2Dは最小二乗直線、3Dは最小二乗平面を使う。衝突判定も同じdimensionを使い、別の次元設定を設けない。
- every_step_opt.py、Random.py、RL.pyをmainと呼ぶ。mainは本人が書くため、明示的な依頼なしに編集しない。
- step用dataclassは各mainで定義する。moduleの関数はnode配列と、必要な部材接続・拘束条件などの引数を受け取る。
- 新しいPythonファイルを提案・追加せず、既存の構成に収める。可視化の処理はlandscape.pyに置く。

## グラフ・図の描画

- matplotlibの設定は `folding_path/00_1106_all/configuration_space/2D.py` を基準にする。本人から個別指定がある場合はそちらを優先する。
- 線・マーカー・系列などの色は、なるべく白黒の濃淡で表現する。系列や状態の区別には線種・マーカー形状も使い、matplotlibの既定の色循環で不用意に多色化しない。
- ポテンシャルなど連続した評価値を色で示す場合は、カラーマップを `viridis` にする。`image.cmap = "viridis"` を基本設定とし、描画関数に必要なら `cmap="viridis"` を明示する。評価値の色分けにはカラーバーを付ける。
- フォントは `font.family = "Times New Roman"` とする。基準サイズは `font.size = 12`、`axes.labelsize = 12`、`xtick.labelsize = 10`、`ytick.labelsize = 10`、`legend.fontsize = 10`。3Dのz軸目盛りも同じ方針でそろえる。
- 軸枠の基準は `axes.linewidth = 0.9`、補助的な原点軸は黒・線幅0.8とし、保存時は `savefig.dpi = 600` を基準にする。サイズ・線幅は図の用途に応じて調整できるが、同じ比較図ではそろえる。
- 初期状態・平坦状態などは白黒の濃淡と異なるマーカー形状で区別する。角度軸は必要に応じてπ表記を使い、同じ尺度の2軸を比較する図では等倍表示を基本とする。
