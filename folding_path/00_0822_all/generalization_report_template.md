# 折り経験の汎化・転移検証

実験開始: 2026-09-14 08:54:57 JST。計算停止: 15:30 JST頃。
予定の5時間を超過し、計算・検証は約6時間36分となった。追加計算は停止済み。
`00_0822_all`内の実装・データ・保存済みモデルを使った追加検証。

## 分かったこと

**D2/D3の経験が、未学習D4やtorusの少量データ学習に役立つ条件は確認できた。ただし、汎化効果は教師経路・学習乱数・追加データ量に依存する。**

- seven-barのD4ゼロショットは成功しなかった。一方、固定された少量のD4教師データでは、同じNNをゼロから学習するより事前学習が有利な条件がある。
- 通常のD4追加学習はD2/D3をほぼ忘れる。旧データを混ぜる方法では、D2/D3を保ちながらD4も学習できた。
- five/seven-barだけで学習したGNNが、NNの追加更新・torus教師ラベルなしに4unit_torusを折った例がある。しかし全5seed平均は16.25%、成功したseedは2/5で、安定したゼロショットではない。
- source学習を長くしたり、sourceでの成功率を上げたりしても、torusのゼロショット・追加学習成績が必ず改善するわけではない。
- 同じD4の複数配置を許す教師で、その教師が実際に通る経路を作り直すと、少ないラベルでD4の成功率が大きく改善した。元の状態に新しい方向を付け直すだけでは同じ改善は得られなかった。
- 「1つのNNが任意の折り紙を折る」ことは未達。D4の主比較は固定7節点のModalStudent、構造間転移は可変節点のGraphModalStudentであり、別の実験系である。

## 1. 評価条件

seven-barはsource32初期形状、D4 support32、validation12、test32。
乱数系列を分け、分割間で近すぎる初期座標を除外した。途中状態を含む教師経路の分割は開始経路単位で維持した。
torusはsupport16、validation8、test16。通常のtorus初期形状は元形状から5～25回の実行可能なランダム歩行で生成した。
さらに100～300回の歩行で16初期形状を作り、初期形状分布を広げた評価も行った。
これらは拘束空間全体からの一様サンプリングではない。

主比較は学習乱数5501～5505の5seed。同じsupportとtest初期形状を共有する。
追加学習は2,000 optimizer更新。各予算ごとに初期重みまたは事前学習重みへ戻し、Adam状態をリセットした。
scratchとpretrainedには、同じ教師データと同じtargetミニバッチ乱数を与えた。
学習率はvalidationで選択し、testを使った学習率選択は行っていない。
D4はscratch=.001、pretrained=.0003。torusはscratch=.003、pretrained=.0003。
選択用validationは1seed・小標本なので、十分なハイパーパラメータ探索とは言えない。

成功は400step以内に、正規化flatness≤0.001、目標広がり誤差≤0.05、部材ひずみ指標≤1e-8を全て満たすこと。
NNの方向・幅に対して部材長拘束への射影と部材交差判定を行い、不適合なら幅を半減する。
**NNの入力にも、NN実行時の一歩の受理条件にも、目的節点座標は与えていない。**
成功判定は広がりと平面化／直線化であり、特定の節点対応や重なり順への完全一致ではない。
有限厚みの面や実物の折り紙を検証したものではなく、部材モデルと実装した交差判定の範囲の結果である。

教師方向は、現在節点をx、教師目的座標をx*、現在の直交モード行列をMとして、
`u* = normalize(M M^T (x* - x))`とした。教師の幅は拘束補正・交差判定後に実際に受理された幅。
損失は`||u_NN - u*||² + 0.2 × (正規化幅_NN - 正規化幅_教師)²`。
教師が有効な一歩を選べなかった状態は幅損失から除外し、非ゼロの方向ラベルは残した。
モード係数そのものではなく、合成した物理方向を教師と比較している。
このNNは、既知の拘束力学からモードを計算できる前提で、その中から折る方向を学習するものである。

## 3. barから4unit_torusへの転移

GraphModalStudentは節点数によらない共有重みを持つ。
入力は現在座標、モード、接続、固定条件、局所部材長、目標D、目標部分空間次元。
モード係数とstep幅を出力する。7節点のbarから20節点のtorusへ同じ重みを適用した。
barの直線化（部分空間次元1）からtorusの平面化（次元2）へ移るため、
トポロジー・節点数だけでなく、目標部分空間次元も未学習の条件へ変わる。
今回の転移効果はこれらの変化をまとめたもので、トポロジーだけの効果には分離できていない。
torusの目的座標は保存済みRL成功終点を教師用に使い、barの事前学習からは除外した。
由来とハッシュは[design.json](torus/design.json)に保存してある。

## 6. 改善しなかった案・予備検証

- Dをone-hotにする案、モード基底に不変な方向出力、D4だけの低ランク追加部分はvalidationで探索した。
  D4未学習カテゴリの重みはsourceでは学べないため、離散表現だけでゼロショットが保証されるわけではない。
  D4追加部分は旧課題の出力を厳密に保ったが、今回の予算では新課題の学習が限定的だった。
- 学生が訪れた状態だけからD4教師データを増やす方法は、予備検証で事前学習の安定した優位性が出なかった。
  教師1経路から始めるbootstrapと、似た停滞状態に偏らないよう間引く条件も別に保存した。
  これらは主比較の5seed testと混ぜない。
- barだけで学習した混合GNNを6unit_torusの提供初期形状1個に直接適用したところ、D2/D3とも全5seedで失敗した。
  この2つの目標がその初期形状から実現可能かを独立に確認できていないため、一般的な不可能性の根拠にはしない。
- 教師座標を使わず、平面化と直径の誤差から直接勾配を作る単純な解析的対照は、4unit通常・広い初期形状で成功しなかった。
  その目的関数・重み・線探索による限定的な対照であり、解析的手法全般が劣るという結論ではない。
- モード基底を直交回転させた診断では通常GNNの方向が少し変わり、射影型は数値誤差程度で一致した。
  ただし基底依存だけが閉ループ失敗の原因とは立証していない。

## 7. 次の検証で優先すること

1. **source replayを基準にする。** 未知Dを追加した後も旧Dを保持する設定をまず固定し、単なるD4専用NN化を避ける。
2. **教師データの選択を評価軸にする。** 独立したsupport収集を複数回行い、同じ問い合わせ予算で、ランダム・経路間均等・停滞／未訪問状態を比較する。
3. **学習する構造を増やす。** five/sevenの2構造だけから普遍的な特徴を得たとは言えない。構造全体をhold-outし、未使用構造で方法選択後の確認を行う。
   bar以外のsourceも入れ、直線化から平面化への条件変更とトポロジー変更を切り分ける。
4. **zero-shotとfew-shotを分ける。** ゼロショット失敗で方針全体を捨てず、新しい教師問い合わせ数と更新数を横軸にしてscratchとの差を測る。
5. **同じDの複数配置を教師側でどう扱うかを固定する。** 分岐の違う勾配を無条件に平均せず、現在状態から一貫した教師選択をする方式を検証する。

現時点で最も支持される方針は、「折り経験を事前学習し、少量の新しい教師データで適応させながら旧データも使う」こと。
ただし、新しい構造や教師データ集合での再検証が必要である。
